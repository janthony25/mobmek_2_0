# Changelog

A running, human-readable log of what shipped and why — reverse-chronological, grouped by
date. One entry per commit, added in the same commit that makes the change. See the rule in
the root `CLAUDE.md` ("Rule: log every commit in `CHANGELOG.md`") for how this is kept current.

## 2026-10-17

- **Add a Xero integration design doc and todo checklist** — `docs/xero-integration-design.md`/`-todo.md` plan a Mobmek-stays-job-centric, Xero-becomes-the-business-overview integration: Phase 1 is a one-way push of generated invoices (+ auto-matched/created Xero Contacts) into Xero; Phase 2 is two-way payment/paid-status sync (push Mobmek-recorded payments to Xero, pull Xero bank-reconciled payments back via webhook + a Journals-API reconcile fallback), flagging a real data-model change (deriving `Invoice.IsPaid` from a tagged payment list instead of a boolean) as a decision checkpoint before it's built. Also documents the broader "what else Xero needs for full visibility" backlog (expenses/bills, GST filing, credit notes, etc.) as explicitly out of scope for now, and flags the in-house Cash Flow v2 bank-import/reconciliation phase as likely redundant once Xero reconciliation is live. No code yet — design only, on a dedicated `xero-integration-design` branch so it doesn't block other work.

## 2026-10-14

- **Add a standalone "Add Customer + Car" kiosk page, gated by a new `AddCustomerAndCar` permission** — a dedicated tablet account can now be handed to a customer to fill in their own details, with no sidebar/navigation and no other page reachable. Reuses the existing `CustomerForm`/`POST /customers/with-car` flow, just hosted bare (`pages/AddCustomerCarPage.tsx`) with a success screen + "Add another" reset. The permission is a frontend-only routing concern — `components/auth/KioskRedirect.tsx` sends any signed-in account whose *entire* permission set is exactly this one permission to `/add-customer-car` from every other path; the `with-car` endpoint itself stays open to any authenticated user (unchanged) so staff's existing "+Add Customer" wizard isn't affected.
- **Fix: signing out of the kiosk page and logging in as a different (e.g. Admin) account landed back on the kiosk page** — `RequireAuth.tsx` remembers the current URL to return to after the next login; signing out *from* `/add-customer-car` meant the next login on that device inherited it, regardless of who logged in, and an Admin passes the kiosk page's own permission check trivially. Fixed by never remembering `/add-customer-car` as a return target; also dropped a redundant sign-out navigate call in `AddCustomerCarPage` that duplicated `RequireAuth`'s job.

## 2026-10-13

- **Add a "Partial Payment" action on invoices** — a new button before "Mark as Paid" opens a wizard (mode of payment, amount, remaining balance, notes) that records a part-payment against an invoice. Record-keeping only for now (no Cash Flow ledger entry — tracked as an open gap); `RemainingBalance` is always computed as `TotalAmount` minus recorded partial payments, never stored. Notes text and a new per-payment "Show on invoice" toggle are the only things editable after creation (amount/date/mode are locked), and deleting one is confirmation-gated. Rejecting an invoice is now blocked while it still has partial payments recorded. The payment history is shown via a dedicated read-only list (`PartialPaymentHistoryList.tsx`, with its own per-row checkbox/edit/delete) — inside the Partial Payment wizard and above the job detail page's Invoice Notes field (live-refreshed right after an action via a new `InvoicesSection.onInvoicesChanged` callback) — never written into `Invoice.Notes` or the job's Job/Invoice notes (an early draft of this did, then was caught and reverted before anything shipped: that text was leaking onto the customer-facing invoice PDF). A payment only prints on the generated PDF once its "Show on invoice" checkbox is ticked (opt-in, off by default), as a plain line after the free-text Notes — no sub-heading. Also **disabled the PDF's green "Paid" banner entirely for now** (some invoices were paid long ago but are still unmarked in the system, and there's a payment-date-accuracy concern with retroactively marking those paid — flip `InvoicePdfService.showPaidBanner` back to `true` once resolved); the banner's amount math was fixed first (it had been double-counting partial payments against the full total) and is left in place behind the flag. New `InvoicePartialPayment` entity + `ShowOnInvoice` column (two migrations), four endpoints, 16 new backend tests.

## 2026-10-12

- **Add a surcharge ("+ Add amount") for catalog services on a job** — some catalog services (e.g. "General Service: $200") are a baseline price that can run higher on a given job; ticking a service in the new `ServicesEditor` now reveals a "+ Add amount" popup that adds a one-off surcharge on top of the catalog price. New `JobServiceLine.AdditionalAmount` field; the invoice/quotation line shows one consolidated price (e.g. $250), never a separate breakdown. 3 new backend tests.
- **Add generic job file uploads (any type), stored in S3** — job photos were image-only; a new "Files" section (`JobFilesSection`/`JobFileDraftPicker`) accepts any file type up to 25 MB, going through the same `IFileStorage` abstraction photos already use so it lands in S3 in production. New `JobFile` entity/controller mirroring `JobPhoto`. 6 new backend tests.
- **Hide the Invoices/Quotations sections while a job is being edited** — the whole list (not just the Generate button) is unnecessary clutter mid-edit; both sections now disappear entirely while `JobDetailPage` is in edit mode and reappear on Save/Cancel.
- **Show Total profit beside Estimated total when creating/editing a job** — computed client-side with the same formula as the backend's `Job.TotalJobProfit`, so operators see margin before saving, not just after.
- **Support multiple CC recipients when emailing an invoice/quotation** — `EmailComposeModal`'s single CC field is now an add/remove list, joined into the existing comma-separated `cc` field on send.
- **Small job-editing polish** — item-name inputs uppercase as typed (matching Title); item-card borders darkened for clearer row separation; "+ Add part" now prepends the new row to the top of the list instead of the bottom.

- **Fix generated invoice/quotation PDFs dropping line breaks in Notes** — `Invoice.Notes` (copied from the job's Invoice Notes, which shows line breaks fine on the job page) was rendered as a single QuestPDF text block, which silently collapses `\n` into one run-on line. Now split per-line before rendering; same fix covers both invoices and quotations (one shared renderer). Live-verified with `pypdf` against a real generated PDF.
- **Fix job back-link losing customer/car context** — opening a job from Customer → Car → that car's jobs list always landed back on the general Job Center instead of the car page, because `CarDetailPage`'s job links were the one place in the app not passing the `location.state` the job page's back-link reads. Now passes it, matching the pattern already used from the customer page and the invoices/quotes list.

- **Fix one invoice drifted out of sync since the legacy cutover** — a newer legacy `.bak` (restored alongside the cutover one for a full table-by-table diff) showed the legacy system had rejected invoice #1518 (Job #486, customer David Fa'anunu) and reissued it as #1556 — same job, same 5 line items, same $6,089.25 total, new due date — after our cutover snapshot was taken. No other customer/job/invoice data had drifted. Applied the equivalent reject-and-reissue to the matching `Invoice` row on both local dev and EC2 (pre-change `pg_dump` backup taken on EC2 first); confirmed neither had been touched since import, so no real edit was overwritten.

- **Add resend-confirmation, admin-set password, and activate-immediately to account creation** — the invite link's 10-minute TTL meant a link that sat unread too long was simply dead with no recourse but deleting and recreating the account; Admins can now hit "Resend confirmation" (`POST /api/accounts/{userId}/resend-confirmation`) to issue a fresh one instead. Also added two optional fields to account creation: an Admin can set the account's initial password directly instead of a hidden random one (emailed to the new hire in plain text alongside the link, HTML-encoded), and an "Activate immediately" toggle that skips the invite-link flow entirely and confirms the account at creation so it can sign in right away. A weak Admin-chosen password now correctly surfaces as "doesn't meet the requirements" instead of the misleading "email already in use". 7 new backend tests; 656/656 passing.

- **Add `scripts/apply-migration.sh` — automatic backup before every production migration** — replaces the fully manual `scp`/`ssh`/`pg_dump`/`psql` sequence documented in `infrastructure/docs/phase-1-plan.md`. The pre-migration backup was previously just a comment telling the operator to remember it; now it always runs and the script aborts before applying anything if the backup looks suspiciously small (same size-sanity check `backup-to-s3.sh` already used). `generate-migration-script.sh`'s header and the infra docs updated to point here instead of the old manual steps.

- **Rename `scripts/publish.sh` to `deploy.sh`** — "deploy" is the accurate term for what it does (put the current `main` onto EC2); "publish" and "release" both imply things this project doesn't do (publishing a package/artifact, cutting a versioned release). References updated in the living docs (`docs/features/*.md`, `.github/workflows/ci.yml`); past `CHANGELOG.md` entries describing it as `publish.sh` are left as-is since that's what it was actually called at the time.

- **Merge `car-make-model.md` into `CarMakes`/`CarModels`** — generated an idempotent SQL script from the file's 69 makes/1231 models using the same case-insensitive find-or-create semantics as the legacy importer's `MakeModelResolver` (`INSERT ... WHERE NOT EXISTS (... LOWER(...) = LOWER(...))`). Ran on local first (31→73 makes, 211→1319 models, verified zero case-insensitive duplicates), then the identical script on EC2 (same numbers, pre-merge `pg_dump` backup taken first). Purely additive — nothing deleted or updated, so no existing car's make/model reference was touched. Closes a gap open since the 2026-07 legacy import.

- **Block letters from the customer phone input at the keystroke level** — `CustomerForm.tsx`'s phone field only had `type="tel"` (a mobile-keyboard hint, not an actual constraint), so a value like "GEORGE" wouldn't be rejected until the Save click hit the backend's existing `[Phone]` validation. Now strips anything that isn't a digit/`+`/`-`/space on every keystroke, matching what the backend already accepts.
- **Fix a typo'd car make on EC2** — "HO;DEN" (should've been "Holden") had one real car/customer attached (rego HEC882). Re-pointed the car to the correct Holden/Captiva make+model (which already existed) and deleted the typo'd make+model, after confirming nothing else referenced them. Pre-fix `pg_dump` backup taken; verified the customer's 2 jobs + 3 invoices are still linked afterward (only the make/model FK changed, not the car's own id).
- **Display customer first/last name and address as uppercase** — `CustomerForm.tsx` inputs now uppercase on keystroke (matching phone/GST/rego elsewhere), and the display side (`CustomerCard.tsx`, `CustomerDetailPage.tsx`, `CustomersPage.tsx`) uses Tailwind's `uppercase` class — presentation-only, no data was touched. Mixed-case legacy data renders uppercase on screen as a result without any backfill needed.
- **Require a car when creating a customer, atomically** — the main "Add Customer" flow can no longer create a customer with zero vehicles, closing the biggest gap in duplicate-customer prevention: since rego is already a hard-blocked unique field, a customer that can't exist without a car means staff can't create a duplicate for a car that's already in the system. New `POST /api/customers/with-car` creates both in one unit of work — nothing is saved, not even the customer, if the car fails validation (duplicate rego/VIN, bad make/model). `CustomerForm.tsx` now collects a full car (reusing `CarForm.tsx`'s cascading make/model select) whenever creating; editing is unchanged. 3 new backend tests including the atomicity regression; 650/650 passing. Not live-browser-verified — local Postgres now mirrors a real EC2 snapshot with no known admin password.

- **Complete the frontend lockfile for macOS too** — the Linux-regenerated lock file (previous entry below) was missing one macOS-only optional entry (`@oxlint/binding-darwin-universal`), discovered when local `npm run lint` broke after the Linux-container verification runs overwrote local `node_modules`. `npm install` on the Mac filled in the gap; the lock file now covers both platforms.
- **Fix (take 2): `package-lock.json` regenerated on the wrong platform** — the first fix (`ce8ff5b`) was generated with `npm install` on macOS, which resolves different optional native-binary variants (rolldown/oxlint/tailwindcss-oxide bindings) than Linux needs — CI's `ubuntu-latest` runner kept failing on `npm ci` even after that commit. Regenerated inside a `node:22` (glibc, matching `ubuntu-latest`) Docker container instead and verified `npm ci`/`build`/`lint` all exit 0 in that same container before committing. `package.json` itself is still unchanged — this is purely platform-conditional lockfile churn (584 insertions/422 deletions, all `@*/binding-*`-shaped entries).

- **Add a migration-drift check to `publish.sh`** — after `git pull` on the box, diffs the pulled commit's migration files against the box's own `__EFMigrationsHistory` (via the same SSH session, no new tooling needed) and fails loudly before rebuilding containers if anything's missing. This is specifically what would have caught the 2026-10-07 outage (code deployed ahead of a migration nobody ran) — CI's build/test gate does not, since it applies migrations fresh rather than checking the live box. Verified both directions: ran for real against EC2 (correctly found zero pending) and against synthetic data with a deliberately-missing migration (correctly flagged it).
- **Add CI: build+test gate on every push to `main`** — `.github/workflows/ci.yml`, two parallel jobs (backend: build/tool-restore/EF-migrate/test against a real Postgres service container; frontend: build+lint). Deliberately push-based, not PR-gated — this repo has never used branches/PRs, so this is a post-push signal to check before `publish.sh`, not a merge-blocking gate. Verified before committing by swapping the real dev DB for a genuinely fresh `postgres:17` container on the same port and running the exact CI sequence — 647/647 passed against a from-scratch schema.

- **Show rego on customer-list vehicle tags** — "2020 Mazda CX-30" is ambiguous when a customer owns two similar cars; now renders "2020 Mazda CX-30 (NCJ955)". Added `Rego` to `CustomerCarSummaryDto` and the frontend `CustomerCarSummary` type. (`4526365`)
- **Phase 6 legacy-import cutover complete — production now has real workshop data** — wiped all dummy workshop data from EC2 (`Customers`/`Cars`/`CarMakes`/`CarModels` + everything cascading from them), ran the fresh cutover `.bak` through a dry-run then a real run into a reset local DB (18/18 reconciliation rows ✅: 510 customers, 530 cars, 759 jobs, 863 documents, 1866 item lines, 269 appointments), then shipped that data to EC2 via `pg_dump`/`psql` rather than running the SQL Server+importer pipeline on the live box. 37 suspected-duplicate customers, 6 duplicate-rego cars, 22 placeholder phones, and 206 single-word names are flagged in the report for manual review, not auto-merged. **Uncommitted** — still pending.
- **Fix: make the invoice/quote sequence-number unique index partial (`WHERE "SequenceNumber" > 0`)** — the plain unique index added 2026-10-06 (`AddInvoiceSequenceNumberUniqueIndex`) broke the legacy importer, which inserts documents with `SequenceNumber = 0` as a placeholder before numbering them for real; two zeros of the same `DocumentType` in one batch violated the constraint. The index's actual job (stopping two *real* concurrent invoice generations from colliding) only ever needs to cover numbers ≥ 1, so excluding 0 fixes the importer without weakening that protection. **Uncommitted** — still pending.
- **Add the first real-Postgres test to the suite** — every one of the other 645 tests runs on EF Core's InMemory provider, which silently ignores the partial index above (`HasFilter` is relational-only), so the bug it fixes could never have been caught by `dotnet test`. `InvoiceSequenceIndexTests.cs` connects to the real dev Postgres instead (needs `docker compose up -d db`) and pins both halves of the index's contract; runs inside a rolled-back transaction so it leaves nothing behind. 647/647 green. **Uncommitted** — still pending.
